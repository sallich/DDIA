# loadgen — фоновая нагрузка

Собственный инструмент на Java вместо готовых wrk или JMeter:
тот же стек, никаких новых образов и языков в стенде.

## Как устроен

| Файл | Что делает |
|---|---|
| `LoadGenerator.java` | управление темпом и ступени ramp-up |
| `Scenario.java` | смешанный CRUD и заведомо неуспешные запросы |

Темп задаётся тикером: каждые 100 мс отправляется одна десятая текущего RPS, каждый
запрос уходит в виртуальный поток Java 21 — медленный ответ не сдвигает расписание.

Ramp-up идёт ступенями, чтобы на графиках был виден выход на плато, а не ступенька
из нуля в полную нагрузку. Дойдя до цели, задача ramp-up снимает сама себя.

## Откуда берутся ошибки

Fault injection в сервис не добавлялся. Ошибки получаются из его обычного контракта:

| Запрос | Код |
|---|---|
| `GET`/`PUT` по случайному UUID | 404 |
| `POST` с пустым именем и отрицательным количеством | 400 |

Доля таких запросов задаётся `ERROR_RATE`.

## Настройки

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `TARGETS` | — | список базовых URL через запятую |
| `TARGET_RPS` | 20 | целевой суммарный RPS |
| `RAMP_UP_STEPS` | 5 | число ступеней выхода на цель |
| `RAMP_UP_STEP_SECONDS` | 30 | длительность ступени |
| `ERROR_RATE` | 0.15 | доля заведомо неуспешных запросов |

В стенде задаются через `.env` с префиксом `LOAD_`.
