# metrics-lib — библиотека золотых сигналов

Снимает latency, throughput и errors rate с REST-ручек, помеченных `@Measured`.
Построена поверх Micrometer, который в версии 1.13 использует Prometheus Java client 1.x.

## Состав

| Файл | Что делает |
|---|---|
| `Measured.java` | аннотация-маркер, публичный контракт библиотеки |
| `MeasuredHandlerInterceptor.java` | собирает route, метод, финальный статус и длительность, отдаёт рекордеру |
| `GoldenSignalsRecorder.java` | публикует гистограмму латентности и счётчик запросов |
| `LatencyHistogramProperties.java` | границы бакетов, `ddia.metrics.latency.buckets[*]` |
| `InstanceTagProperties.java` | свойства `ddia.metrics.instance.*` — контракт конфигурации |
| `MeasuredHandlersEndpoint.java` | `/actuator/measured` — список инструментированных ручек для генератора |
| `MetricsAutoConfiguration.java` | поднимает интерсептор, регистрирует его в MVC, объявляет бин общих лейблов |
| `META-INF/spring/...AutoConfiguration.imports` | делает автоконфигурацию активной |

Приложению не нужно ничего импортировать: библиотека подхватывается самим фактом
присутствия в classpath, прикладной код видит только аннотацию.

## Метрики

```
ddia_http_request_duration_seconds   гистограмма, лейблы route, method, metric_type=latency
ddia_http_requests_total             счётчик,     лейблы route, method, status, metric_type=throughput
```

Общие лейблы на всех метриках реестра: `pod`, `datacenter`, `deployment` — навешиваются
через `MeterRegistryCustomizer`, то есть до регистрации метрик.

Статус не является лейблом гистограммы намеренно: он умножил бы 17 бакетов на число кодов
ответа. Latency берётся из гистограммы, traffic и errors rate — из счётчика.

Перцентили считаются на чтении через `histogram_quantile` поверх `sum by (le)`. Бакеты —
счётчики, они складываются корректно, поэтому агрегация по нескольким подам и датацентрам
даёт честный перцентиль по объединённой выборке.

Лейбл `metric_type` добавлен по букве ТЗ, которое перечисляет «тип метрики» в одном ряду
с подом, датацентром и идентификатором ручки. По соглашению Prometheus тип кодируется
именем метрики, так что лейбл избыточен, но стоит ноль дополнительных рядов.

## Конфигурация

Библиотека владеет своим пространством имён и не знает про имена env-переменных приложения:

```
ddia.metrics.instance.pod
ddia.metrics.instance.datacenter
ddia.metrics.instance.deployment
ddia.metrics.latency.buckets[*]
```

Сервис мостит в них свои переменные в `service/src/main/resources/application.yaml`.
Незаполненное свойство не роняет приложение — подставляется `unknown`, и это сразу видно
в выдаче метрик.

Границы бакетов по умолчанию подобраны под измеренное распределение демо-сервиса
(p50 около 1.9 мс, p99 около 3.8 мс): плотно в районе 1–5 мс, разреженный хвост до секунды.
Дефолты Micrometer начинаются с 1 мс, и на более быстром сервисе все перцентили сливаются
в одну линию — поэтому границы заданы явно.

## Обнаружение ручек

`/actuator/measured` отдаёт список ручек, помеченных `@Measured`, и имена метрик — контракт
для генератора дашборд. Источник — реестр Spring MVC, поэтому список точный с момента старта
и не зависит от того, был ли по ручке трафик.
